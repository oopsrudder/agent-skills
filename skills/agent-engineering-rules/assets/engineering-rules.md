# 工程与代码规则

> 适用：所有 agent 在执行代码实现、修改、重构、排障任务时的行为约束。
> 优先级：项目内规则可覆盖本规则的「倾向性建议」，但本规则的「禁止」项不因项目规则宽松而失效，除非用户当次明确豁免。

## 1. 先根因，后修复

- 动手前先定位根因：读调用链、追数据流、复现问题，先弄清「为什么错」，再决定「改哪里」。
- 修复要落在正确的层次：优先用更合理的 API、更准确的状态模型、更清晰的架构边界来消除问题。
- 禁止表层补丁：吞异常、加 try/catch 兜底、堆防御性判空掩盖时序问题、复制一份逻辑绕开缺陷、调大超时/重试次数掩盖失败，均视为未修复。
- 无法定位根因时，必须直接说明「当前只是缓解」，并列出待验证的根因假设，不得当作已完成交付。

## 2. 定时器

- 默认禁止用定时器规避时序、生命周期、渲染时机、状态同步类问题。
- 允许使用的前提（需同时成立）：没有事件驱动的替代方案；不用会造成真实功能缺陷；延迟或轮询本身就是需求语义（节流、退避、轮询外部状态、动画帧、超时控制）。
- 使用时必须同时给出：① 一行注释说明为什么必须用（why）；② 对应的清理逻辑（clearTimeout / clearInterval / AbortController / 框架的 effect 清理）；③ 组件卸载或任务结束后不再触发的保证。
- 禁止：setTimeout(0) 掩盖更新顺序问题；setInterval 轮询本地状态；随机延迟等待渲染完成；用定时器模拟事件。

## 3. React：副作用最小化

- 优先用状态派生（render 里能算出来的就不要存进 state）、事件驱动（在事件处理器里直接更新）、组件组合（props / children 拆分职责）来表达逻辑。
- useEffect 只用于与外部系统同步：订阅、命令式 DOM 操作、网络与存储、第三方库实例、动画。
- 禁止用 useEffect 做：由 props/state 推导的值、事件已能覆盖的流程、链式 setState 推进状态机、只在挂载时跑一次的「伪构造函数」（改用模块作用域、useState 惰性初始化或数据层）。
- 每个 effect 必须正确处理依赖数组与清理函数；要关闭 exhaustive-deps 必须写明理由。
- 遇到「监听某值变化再做事」，先反问：这个变化是不是已经发生在产生它的事件里？能在源头处理就不要在 effect 里追。

## 4. 注释

- 只写读代码看不出来的信息，按 who / why / what 组织：作用于谁、为什么必须这样写、达成的效果边界。
- 必须写：非直觉的取舍、绕过上游缺陷的原因、性能敏感点、外部协议或时序约束、魔法值的来源。
- 禁止：复述代码、逐行翻译、装饰性分隔线、大段注释掉的旧代码、把 TODO 当留白、在注释里写变更流水账。
- 命名能表达的交给命名，注释只解决命名解决不了的问题。

## 5. 导入与依赖

- 提交前逐个审查 import：未使用的、仅类型却未用 type-only 导入的、循环依赖的、跨层（UI 直接引数据层或服务端实现）的、带模块级副作用的，全部删除或改写。
- 主线程不得导入渲染线程（Worker / Renderer）模块；重计算、大体积依赖、解析类库应下沉到 Worker 或改为按需动态加载。
- 避免长任务阻塞主线程；大批量处理要分批或交给 Worker。
- 新增依赖要说明现有能力为何不够；能用平台 API 或已有依赖解决的不引新包；引包需考虑体积与 tree-shaking。
- 改动后不再被引用的导出、文件、样式、配置一并删除，不留「也许以后有用」。

## 6. 目录与整洁

- 按功能分文件夹组织：同一功能的组件、hooks、类型、测试、样式放在一起；只有真正跨功能复用的才进共享层。
- 保持单向分层：UI → 状态/hooks → 数据访问 → 基础设施，禁止反向依赖。
- 收尾清理：临时方案、调试日志、注释掉的代码、临时开关、mock 数据、未使用的文件与依赖。
- 不留「以后再修」：能当场解决的当场解决，解决不了的写进交付说明。

## 7. 文档

- 未经用户明确要求，不创建新的 Markdown 文档（README、说明、总结、方案书、变更记录）。
- 需要解释时，优先写在必要的代码注释、提交信息或回复正文里。
- 不为「留痕」生成报告文件。

## 交付前自检

1. 根因说清楚了吗？改的是原因还是症状？
2. 引入了定时器吗？原因与清理都写了吗？
3. 有能用派生或事件替代的 useEffect 吗？
4. 注释只在必要处吗？有没有复述代码？
5. 导入干净吗？有没有主线程引入重模块或渲染线程模块？
6. 留下临时方案、死代码、调试残留了吗？
7. 有没有未经要求新增 Markdown 文档？
